# ADR 0005：设备代码分仓，参赛编排集中

- 状态：已接受
- 日期：2026-11-14

## 背景

Elfin5 工作站位于 `ctl-elfin5`，两款 leapROS 小车位于独立的 `ctl-leapros2car`。两者已有各自的源码仓库、构建入口、实机诊断和未提交修改。为了统一接入而复制驱动源码或迁移全部工作区，会破坏既有验证边界；完全分散 AgentArts 技能与参赛配置，又会使统一演示和版本追踪困难。

## 决策

采用“设备代码分仓，编排集中”：

- Elfin5 与 leapROS 的驱动、设备专用配置和实机验证分别留在所属仓库。
- RoboNeuron 通用能力修改留在固定版本的 RoboNeuron fork，不把设备专用源码复制进去。
- AgentArts 任务技能、统一运行配置、跨设备演示和参赛材料集中在 `ctl-elfin5`。
- 跨仓库通过显式 ROS/MCP 接口契约和可追溯版本集成，不以复制源码或搬运构建产物代替依赖管理。

## 后果

- 各设备现有构建和实机验证入口保持独立，降低布局迁移风险。
- 统一演示需要记录两个设备仓库与 RoboNeuron fork 的兼容版本。
- `ctl-elfin5` 中的集中编排不能假设 leapROS 工作区是自己的 colcon 子工作区。
- 设备接口变化需要同步更新适配器与任务技能，并通过跨仓库集成检查发现漂移。
- 一个月内不需要新建第三个参赛总仓库。

## 备选方案

- 全部集中到 `ctl-elfin5`：统一目录但会改变 leapROS 现有构建和验证边界。
- 全部留在各设备仓库：设备独立性强，但 AgentArts 技能与参赛证据分散。
- 新建参赛总仓库：编排边界清晰，但增加仓库、版本和交付管理成本。
