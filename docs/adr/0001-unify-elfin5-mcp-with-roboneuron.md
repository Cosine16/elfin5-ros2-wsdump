# ADR 0001：将 Elfin5 MCP 能力统一到 RoboNeuron

- 状态：已接受
- 日期：2026-11-14

## 背景

仓库已有独立的 Elfin5 MCP 服务，提供状态查询、运动、使能、停止和末端 IO 等能力。参赛主线要求同一 Agent 接入 Elfin5 工作站与两款 leapROS 小车，并由 RoboNeuron 同时承载直接执行路径和 VLA 闭环。若长期并行保留两套同能力 MCP，会产生重复工具、语义漂移和运动控制边界不清的问题。

## 决策

以 RoboNeuron 作为本项目统一的 Agent 侧机器人中间件。保留现有 Elfin5 工具的能力语义与安全检查，将其迁移为 RoboNeuron 后端或工具；AgentArts 不并行连接两套提供相同 Elfin5 能力的 MCP 服务。

现有 Elfin5 MCP 是迁移时的行为参照。具体工具命名、兼容别名和旧服务退役时间由后续接口清单与验证结果确定。

## 后果

- Agent 面对统一的工具与执行生命周期，直接执行和 VLA 闭环可以共享同一中间件边界。
- 需要完成迁移和回归验证，不能假设现有 stdio MCP 可以直接被云端 AgentArts 使用。
- RoboNeuron 当前自动工具生成主要覆盖 ROS topic 消息；Elfin5 的 service、action、TF 和 IO 能力需要显式适配，不能宣称由 schema 自动生成全部覆盖。
- 统一工具入口不等于允许多个运动发布者并行控制同一机器人，控制权设计仍需单独验证。

## 备选方案

- 两套 MCP 并存：初期改动较少，但削弱统一接入主线并保留重复能力。
- 完全重写且不参考现有工具语义：接口可重新设计，但迁移风险和验证成本更高。
- 永久使用薄适配层：保留较多实现自由度，但长期边界不明确。
