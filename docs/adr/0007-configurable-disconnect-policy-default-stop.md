# ADR 0007：可配置断链策略默认停止并按技能允许续跑

- 状态：已接受
- 日期：2026-11-14

## 背景

AgentArts 与实验室边缘网关断链时，导航、短时机械臂服务和本地 VLA 闭环具有不同的连续性与安全需求。固定全部停止会中断本可独立完成的本地任务；固定全部续跑又会让失去云端监督的长任务扩大风险。项目需要保留演示连续性，同时确保默认行为和配置来源明确。

## 决策

采用可配置断链策略，默认值始终为停止：

- 只有任务开始前显式选择续跑、且该技能属于断链续跑白名单时，活动本地执行单元才可继续。
- 配置缺失、无效或技能未获准续跑时均按停止处理。
- 本地启动 flag 提供默认值，本地授权节点可通过锁存 topic 在设备空闲时修改；云端不能在任务执行中途改变策略。
- 续跑只覆盖已经下发并在实验室侧运行的原子动作、导航目标或闭环实例，云端 Agent 尚未下发的新步骤不得继续执行。
- 停止路径仍需取消活动导航或 VLA、底盘零速、机械臂受限停止并禁止新任务；吸盘不因断网自动释放，由人工检查后接管。

## 后果

- 演示可针对经过验证的本地技能保留断链连续性，同时未配置场景具有确定的停止行为。
- 每个技能需要声明是否允许断链续跑，并分别验证停止和续跑两条路径。
- 运行时需持久提供锁存策略状态，且只允许本地授权节点在空闲时修改。
- 云端任务即使在断链前获得任务级授权，也不能把该授权解释为继续执行尚未下发的步骤。
- 断网期间吸盘保持而不是自动释放，可以避免物料坠落，但现场恢复后仍需人工检查吸附与负载状态。

## 备选方案

- 默认全部续跑：连续性较高，但失去云端监督时风险更大。
- 所有任务一律停止：规则简单，但牺牲可独立完成的本地任务。
- 仅 Nav2 可续跑：首版规则具体，但无法覆盖其他经过验证的本地技能。
- 云端 MCP 参数控制：编排方便，但云端误设和最后状态一致性难以作为安全依据。
