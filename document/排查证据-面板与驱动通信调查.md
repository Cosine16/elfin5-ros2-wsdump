### 证据 7: enable_state 长窗口(60s 以上)后到达


### 证据 9: QoS 与发布者归属

```bash
ros2 topic info -v /enable_state
# → 发布方: 节点 elfin_hw, RELIABLE/VOLATILE
# → 订阅方: _ros2cli_*(echo), BEST_EFFORT/VOLATILE
```

RELIABLE 发布 + BEST_EFFORT 订阅为兼容组合(订阅要求 ≤ 发布提供), QoS 不是障碍; 发布者确认是驱动节点 `elfin_hw`。

> 支持: [[排查推测-面板与驱动通信调查#推测 3: rqt 看不到节点是 sudo 跨用户的 DDS 共享内存(SHM)权限问题 ❌ 证伪]]

### 证据 12: 测试过程中的干扰项与修正记录

调查初期三组"数据不通"的阴性结果均为测试方法问题, 修正后复测均为阳性:

| 干扰项 | 现象 | 修正 |
|---|---|---|
| `bash -c 'source ... && 命令 &'` | `&` 把整条链丢后台, 前台无环境 | 拆行: `source ...; 命令A & 命令B` |
| `ros2 topic pub \| head` 管道 | Python 块缓冲, kill 后输出丢失 | 后台任务 + 读输出文件 |
| `pkill -f 'chatter_test'` | 匹配到自身命令行, shell 自杀(exit -1) | 用任务管理或精确 PID |
| `ros2 topic echo --once` | Foxy 无此参数(Humble 才有) | `timeout N ... \| head` |
| `ros2 --version` | Foxy 无此参数 | 用 `ros2 doctor` / `ros2 pkg prefix` |

> 支持: [[排查推测-面板与驱动通信调查#推测 4: "看不到"的真实原因是环境/缓存/时间窗口三重叠加 ✅ 证实]]
